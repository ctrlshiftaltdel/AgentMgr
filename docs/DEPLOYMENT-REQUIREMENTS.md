# 生产部署要求

- 日期：2026-10-16
- 范围：首期中国大陆部署（章程 O1/O5 决策）
- 用途：把散落在任务台账审查记录中的部署前提固化为仓库内可追溯文档

## 1 结论摘要

本文汇总截至 2026-10-16 已确定的部署前提与策略；这些前提不满足时，仓库内已有的若干安全防护会失效。分为硬要求、本地开发临时做法、待验证项三类。

- **硬要求**（不满足即防护失效，不可省略）：数据库角色与权限分离（第 2 节）、服务身份与进程隔离（第 3 节）、生产环境 Python 解释器与依赖固定（第 4 节）、备份与恢复演练（第 5 节）、模型与数据边界（第 7 节）。
- **本地开发临时做法**（仅限本机，不可外推为生产做法）：unix socket + peer 认证（第 2 节）、所有 Worktree 共享主工作树 `.venv`（第 4 节）。
- **待验证项**（尚无实测结论，见第 8 节）：生产主机规格、多 Profile 内核级隔离负面测试、多路复用凭据 fail-closed、微信真实账号路由与鉴权、备份周期与恢复演练。

## 2 数据库角色与权限分离（硬要求）

- 应用运行期角色**不得拥有 DDL 权限**：审计表 audit_events 的只增不改由 BEFORE UPDATE/DELETE 触发器强制，而 ALTER TABLE ... DISABLE TRIGGER 只有表属主或超级用户可执行；若应用角色是表属主，该防护可被绕过（W1-5 审查时已实测确认）。
- 迁移（alembic upgrade/downgrade）必须由**独立的 DDL 角色**执行，与运行期角色分离。
- 认证：本地开发用 unix socket + peer 认证（角色 agents，无口令落盘）；生产必须改为口令或证书认证，且口令不得进入仓库、日志或模型提示词。
- 应用角色最小权限：只授予所需表的 SELECT/INSERT/UPDATE/DELETE；审计表只授予 INSERT 与 SELECT。
- 待建立：角色与授权脚本。

## 3 服务身份与进程隔离（硬要求）

- Hermes Profile 只隔离数据与凭据作用域，**不是操作系统边界**（W0-2 §3 与 W0-7 §5.1 已实测：同一 OS 用户可互读 Profile 目录）。
- 因此“员工 A 无法读取员工 B 的文件/进程/网络/临时目录”必须由部署层强制：每 Profile 独立 systemd 服务账户（User=）、独立 UID、独立 TMPDIR、ProtectSystem/ProtectHome，必要时容器或 namespace。
- 该隔离必须用**负面测试**证明，不得以文档声明代替。
- 生产 Profile 主机：同类 Debian Linux，内存更多、CPU 更快；具体规格待真实活动负载测试（章程 O1）。

## 4 Python 环境策略

- 解释器由仓库根 `.python-version` 固定为 3.13；不得用系统 python3 直接跑业务代码。
- 依赖由 uv 管理（pyproject.toml + uv.lock），**不得使用 pip**。
- 当前本地开发做法：所有 Worktree 共享主工作树的 `.venv`（环境变量 UV_PROJECT_ENVIRONMENT=/home/agents/ajaimgr/.venv），以避免在 1.9 GiB 的机器上重复安装依赖。
- **切换要求**：一旦把 ORCHESTRATION-PROJECT.md 的并发上限从 1 提高（允许两个执行实例同时运行），必须改回“每个 Worktree 各自生成 .venv”，否则一个 Worktree 的 uv sync 会就地改写另一个正在使用的环境。
- 生产同样固定 3.13 并用 uv sync 安装锁定版本。

## 5 存储与备份

- 附件采用内容寻址存储（AJAIMGR_STORAGE_ROOT，默认 var/storage），sha256 派生路径；数据库与附件分别备份。
- 数据库备份用 `pg_dump`；离线版规则包时期遗留的本地任务库（`.orchestration/`，仅历史归档）如需留存单独复制即可（本机 SQLite 副本不作为生产备份手段；任务与验收现已纳入 GitHub Issues）。
- 备份工具已建立：`ops/backup.py`（数据库 + 附件 + 任务库 → 单一归档，含 `manifest.json` 逐成员 sha256 与关键表行数、`<归档>.sha256` 校验和，凭据类文件排除并扫描断言）与 `ops/restore.py`（恢复到干净目标并 13 项逐项校验，任一项不符即非零退出码）；测试见 `app/tests/ops/test_backup_restore.py`。
- 备份必须存放于**生产主机之外**；必须完成一次真实恢复演练后才算验收通过（章程成功标准）。本机同机演练已于 2026-10-16 完成（13 项校验通过），**但异地存储与跨主机恢复仍未做**，因此该条尚未满足。
- 附件存储根与数据库均位于中国大陆可控环境（章程数据处理约束）；异地副本同样受此约束。
- 备份周期、保留代数、恢复演练频率与责任人，以及本机演练与生产环境的差异：见 [BACKUP-RESTORE.md](BACKUP-RESTORE.md)。

## 6 时钟与时间源

- Outbox 的退避与抢占使用**应用侧时钟**（datetime.now(UTC)）判断 available_at；单机部署无影响。
- 多机部署必须保证各主机时钟同步（NTP），否则退避与抢占边界会出现偏差；或改为使用数据库时钟。
- 时间戳统一存 UTC（timestamptz），展示层再转本地时区。

## 7 模型与数据边界

- 送入模型的数据受字段白名单约束：默认拒绝、逐字段放行（W0-5 §3）。
- 日志禁止项：凭据与 token、完整渠道用户 ID（用哈希）、附件原文、OCR 原文全文、A 类字段原文。
- 模型供应商与模型侧安全由项目所有者自行把控（章程 O5 已决策）。
- 审计记录关联实际人员（actor_id），不得写入模型名字或角色名。
